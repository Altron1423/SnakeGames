# Документация архитектуры

В данном документе приведено высокоуровневое описание архитектуры программного обеспечения проекта Snake MMO.

## 🏗️ Обзор

Проект основан на **клиент-серверной архитектуре**, предназначенной для поддержки как локального одиночного режима игры, так и сетевых многопользовательских сессий. Сервер выступает в роли "источника истины" (source of truth), управляя игровым состоянием, физикой и синхронизацией игроков, в то время как клиент отвечает за обработку пользовательского ввода, локальное представление состояния и рендеринг.

## 🌐 Сетевой уровень

Связь между клиентом и сервером осуществляется через кастомный протокол, построенный на базе **TCP-сокетов**.

### Протокол связи
- **Формат**: Данные сериализуются в формате JSON.
- **Разделители**: Каждое сообщение заключено в символы `<` и `>` (например, `<{"key": "value"}>`), что обеспечивает целостность сообщений и позволяет эффективно читать поток данных в асинхронном режиме.
- **Асинхронная обработка**: Сервер и клиент используют неблокирующие сокеты для управления множеством подключений и непрерывными потоками данных без прерывания основного игрового цикла.

### Объекты передачи данных (DTO) и Мапперы
Для обеспечения типизации и четкого разделения между сетевым протоколом и игровой логикой используются:
- **DTO**: Классы, определенные в `libs/dtos`, представляют структуру сообщений, передаваемых по сети (например, `ConnectClientDTO`, `GameDataToClientDTO`).
- **Мапперы**: Модуль `libs/mappers` предоставляет утилиты для преобразования этих объектов DTO в словари (для сериализации в JSON) и наоборот.

## 🎮 Основной игровой движок

Игровой движок разделен на две основные части: **Игровой сервер** и **Игровой клиент**.

### 1. Игровой сервер (`libs/game/game_server.py`)
Сервер отвечает за:
- **Управление состоянием**: Поддержание достоверного состояния игрового мира, включая всех игроков, врагов и карту.
- **Игровая логика**: Обработка действий игроков (например, движения, действий) и расчет нового состояния игры.
- **Жизненный цикл сущностей**: Создание игроков, управление их подключением/отключением и появление врагов-ИИ.
- **Синхронизация**: Периодическая рассылка обновленного состояния игры всем подключенным клиентам.

### 2. Игровой клиент (`libs/game/game_client.py`)
Клиент отвечает за:
- **Обработку ввода**: Сбор пользовательского ввода (клавиатура, мышь) и отправку его на сервер.
- **Локальную симуляцию**: Поддержание упрощенного локального представления игрового мира для плавного рендеринга.
- **Рендеринг**: Использование `pygame` для отрисовки игрового мира, сущностей и пользовательского интерфейса.
- **Синхронизацию сущностей**: Обновление состояния локальных сущностей на основе данных, полученных от сервера.

## 🧩 Ключевые модули

| Модуль | Ответственность |
| :--- | :--- |
| `libs/conecting` | Управление низкоуровневыми соединениями ( `ServerConnector`, `ClientConnector`). |
| `libs/graphics` | Отвечает за визуальный вывод, включая окна, камеру и элементы интерфейса. |
| `libs/loaders` | Отвечает за загрузку игровых данных (карты, определения сущностей, анимации) из JSON-файлов. |
| `libs/save` | Управляет сохранением состояния игры и данных игрока на файловой системе. |
| `libs/math` | Предоставляет необходимые математические операции (векторы, 2D/3D математика). |

## 🔄 Пример потока данных (Движение)

1. **Клиент**: Пользователь нажимает клавишу управления $\rightarrow$ `GameClient` обновляет локальную ориентацию $\rightarrow$ `ClientConnector` отправляет `GameDataToServerDTO` с действием движения на сервер.
2. **Сервер**: `ServerConnector` получает сообщение $\rightarrow$ `GameServer` получает действие $\rightarrow$ `GameServer` обновляет позицию игрока в авторитетном состоянии игры.
3. **Сервер**: `ServerConnector` рассылает обновленную позицию игрока всем клиентам через `GameDataToClientDTO`.
4. **Клиент**: `ClientConnector` получает обновление $\rightarrow$ `GameClient` обновляет позицию локальной сущности $\rightarrow$ `pygame` отрисовывает новую позицию на следующем кадре.
